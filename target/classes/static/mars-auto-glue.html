AGV-中控-工控机-PLC 程序运行控制流程说明

更新时间：2026-07-29

本文按当前项目代码整理，用于说明从 AGV 上报任务，到中控分发指令给工控机 station，再到 station 读取 PLC 信号并控制生产流程的完整运行逻辑。

涉及项目：

  • 中控服务：split-glue
  • 工控机服务：station

核心代码位置：

  • AGV 接口入口：split-glue/src/main/java/com/sage/controller/AmrController.java
  • AGV 业务处理：split-glue/src/main/java/com/sage/service/impl/AmrServiceImpl.java
  • 中控到 station WebSocket：split-glue/src/main/java/com/sage/websocket/DeviceWebSocketHandler.java
  • 中控互斥控制：split-glue/src/main/java/com/sage/guard/MachineLineGuard.java
  • 中控 AGV 互斥切面：split-glue/src/main/java/com/sage/guard/MachineTaskGuardAspect.java
  • station 接收中控命令：station/src/main/java/com/sage/websocket/CenterHandlerAdapter.java
  • station 扫码循环：station/src/main/java/com/sage/service/impl/ScanCodeServiceImpl.java
  • station PLC/投料/称重/人工介入主逻辑：station/src/main/java/com/sage/service/impl/MachinsServiceImpl.java

三、正常上料到生产的详细步骤

1. AGV 发送送料物料数据

AGV 调用：

POST /amr/feedingInformation

典型参数：

{
  "feedingLine": "1",
  "agvNum": "AGV001",
  "partNum": "xxx"
}

中控执行逻辑：

  1. MachineTaskGuardAspect.guardFeedingInformation() 先做机台互斥判断。
  2. 根据 feedingLine 匹配机台号。
  3. 创建 DeliveryOrder，初始状态 orderStatus=0。
  4. 把生成的 orderId 写回 AGV 数据 map。
  5. 通过 WebSocket 发给对应 station：
{
  "type": "cmd",
  "command": "agvData",
  "line": 1,
  "parameter": {
    "feedingLine": "1",
    "agvNum": "AGV001",
    "orderId": "123"
  }
}

station 执行逻辑：

  1. CenterHandlerAdapter.agvData() 接收 agvData。
  2. 将 AGV 数据放入 MachinsServiceImpl.ridgeMap 缓存。
  3. 这个缓存后续用于新建批次、找 orderId、同设备转线复用物料基础数据。

前端运行状态：

1：AGV上料中

2. AGV 到达准备点

AGV 调用：

POST /amr/preparationPoint

典型参数：

{
  "agvNum": "AGV001",
  "productionLine": 1
}

中控执行逻辑：

  1. MachineTaskGuardAspect.guardPreparationPoint() 校验 AGV 回调产线仍是当前机台占用产线。
  2. 中控向 station 下发 PLC 指令：
{
  "command": "send_plc_bool",
  "parameter": {
    "addressValue": "DB32.0.0",
    "parameters": true
  }
}

station 执行逻辑：

  1. CenterHandlerAdapter.sendPlc() 收到 send_plc_bool。
  2. station 调用 plcClient.sendBool("DB32.0.0", plcIp, true)。
  3. 该点位表示 AGV 到位/开门相关信号。

前端运行状态：

2：AGV到达准备点

3. AGV 送料完成并离开

AGV 调用：

POST /amr/theFeedingIsComplete

送料完成参数：

{
  "agvNum": "AGV001",
  "productionLine": 1,
  "shipping": 1
}

中控执行逻辑：

  1. MachineTaskGuardAspect.guardFeedingComplete() 校验回调产线是否允许。
  2. 中控先发 AGV 退出/关门信号：
DB32.0.1 = true
  1. 因 shipping=1，调用 theProcessBegins(machineNum, productionLine)。
  2. 中控向 station 下发扫码命令：
{
  "command": "scanTheCode",
  "line": 1,
  "parameter": 1
}
  1. 设置 afitMap[line].line_state=1，表示当前产线进入运行占用状态。

前端运行状态：

3：送料完成开始扫码

4. station 常规抓取前切换产线

station 收到 scanTheCode 后先执行：

machineService.determineProductionLine(cmd.getLine())

这一步是“常规抓取前切线”，和人工介入后的“同设备转线”完全不是一套逻辑。

常规抓取前切线 PLC 点位：

目标本地产线PLC 点位
本地 1 线DB32.10.5 = true
本地 2 线DB32.10.6 = true
本地 3 线DB32.11.1 = true

随后进入扫码循环。

5. station 扫码循环

代码入口：

station ScanCodeServiceImpl.scanTheCode()

循环读取逻辑：

PLC 点位作用
DB34.34.7当前代码作为是否跳过扫码循环的前置判断
DB34.34.2机械异常
DB34.6.3D 栋二维码读取完成信号
DB100.1260.0D 栋二维码字符串结果
DB32.10.3D 栋二维码确认信号

流程：

  1. 进入扫码，前端仍显示 3：送料完成开始扫码。
  2. 每秒检查一次 PLC 信号。
  3. 如果 DB34.34.2=true，认为机械异常，返回 error=true。
  4. 如果 DB34.6.3=true，读取 DB100.1260.0 的二维码结果。
  5. 读取成功后写 DB32.10.3=true 确认。
  6. 将扫码结果返回中控：
{
  "command": "scanTheCode",
  "parameter": {
    "d": "二维码",
    "error": false,
    "transfer": false,
    "feedingLine": 1
  }
}
  1. 如果 5 分钟超时，返回 transfer=true，station 结束扫码流程。
  2. 如果人工点击“强制结束当前流程”，scanStopRequested=true，下一轮循环返回 transfer=true 并退出。

6. 中控根据扫码结果查询 MT 并回发 station

中控收到 station 的 scanTheCode 回传后：

  1. DeviceWebSocketHandler.scanTheCode() 解析扫码结果。
  2. 调用 mtService.getTheDetails(qrCode) 查询物料明细。
  3. 组装 ridgepole_map。
  4. 向同一 station 下发：
{
  "command": "mtData",
  "line": 1,
  "parameter": {
    "d": [
      {
        "barNo": "...",
        "material": "...",
        "materialDesc": "...",
        "quaterQty": "...",
        "line": "S1"
      }
    ]
  }
}

station 收到 mtData 后：

  1. MtServiceImpl.dataContrast(map, line) 做物料数据对比。
  2. 对比成功后进入 MachinsServiceImpl.executionLogic(map, line)。

7. station 进入 executionLogic 投料主循环

进入时 station 会上报：

6：工控机投料中

核心动作：

  1. 将 executionStopFlags[line] 清空为 false。
  2. 将当前 MT 物料明细放入 materialDataCache[line]，供后续同设备转线复用。
  3. 根据产线算本地产线。
  4. 如果当前本地产线 batchActualWeight=0，创建新批次：
  • 生成唯一 batchId
  • 记录批次开始时间
  • 根据 ridgeMap[line].orderId 找到订单
  • 把 DeliveryOrder.orderStatus 改成 1：执行中
  1. 读取当前物料 GRD、BarNo。
  2. 进入 while 主循环，每 5 秒检查一次 PLC 状态。

executionLogic 主循环关键 PLC 点位：

PLC 点位作用
DB34.0.3PLC 退料信号
DB36.1.0PLC 自动模式，false 表示被切手动
DB34.34.2PLC 机械异常
本地 1 线 DB34.6.7批次重量达标/请求人工介入
本地 2 线 DB34.7.1批次重量达标/请求人工介入
本地 3 线 DB34.34.1批次重量达标/请求人工介入

循环内分支：

条件station 处理
人工强制结束标记为 true退出循环，上报 8 请求人工介入
DB34.34.2=true进入异常处理
重量达标点位为 true设置 artificial=true，跳出循环，后续请求人工介入
DB34.0.3=truePLC 请求退料，进入称重保存和 MT 上报
DB36.1.0=falsePLC 当前是手动模式，流程结束，上报 10

四、PLC 退料信号后的称重和批次判定

当 executionLogic 读到：

DB34.0.3 = true

station 执行：

processReturnMaterial()
saveLabelRecordAndReportMt()

称重相关点位：

PLC 点位作用
DB34.16.0地磅称重结果可读取信号
DB34.18.0地磅重量 float
DB34.16.1是否空托判断

称重流程：

  1. station 等待 DB34.16.0=true。
  2. 如果一直不来，会持续打印“PLC正在地磅称重,等待中...”。
  3. 如果人工点击“强制结束当前流程”，称重循环读取到退出标记后返回 null 并退出。
  4. 读取 DB34.18.0 重量。
  5. 根据当前批次 batchId + barNo 保存或累加 LabelRecord.qty。
  6. 累加本地 LineData.batchActualWeight。
  7. 根据 DB34.16.1 判断是否空托，写 LabelRecord.isCompleted。
  8. 保存 LabelRecord。
  9. 调用 reportMt()，把当前批次渐进式上报 MT。

称重完成后，station 上报：

7：工控机退料中

然后进入 lotDetermination() 判断下一步。

五、批次判定后的两种主分支

1. 批次未达标，退料后继续补料

当不是人工介入、不是异常、不是转件时，station 认为：

未达到批次量，先退料，之后继续叫料

station 向中控发送：

{
  "command": "send_agv",
  "line": 1,
  "parameter": "stripping_feeding"
}

中控收到后：

theStatusOfTheMachine[line] = 3

含义是：

请求退料，并且退料完成后还要继续叫料

之后 AGV 拉走当前托盘，完成后调用：

POST /amr/theFeedingIsComplete

参数：

{
  "agvNum": "AGV001",
  "productionLine": 1,
  "shipping": 2
}

中控收到 shipping=2 时会先读取退料前状态：

beforeLineStatus = theStatusOfTheMachine[line]

如果 beforeLineStatus=3，说明是“退料后继续补料”，中控执行：

theStatusOfTheMachine[line] = 1

前端运行状态：

5：退料完成正在呼叫补料

这条线仍然没有完全结束，互斥不会释放。

2. 批次达标，请求人工介入

当 station 在 executionLogic 中读到对应本地产线重量达标点位：

本地产线达标点位
本地 1 线DB34.6.7
本地 2 线DB34.7.1
本地 3 线DB34.34.1

station 设置 artificial=true，跳出主循环，执行：

trigger_ait(line)

station 向中控发送：

{
  "command": "manualChoose",
  "line": 1,
  "parameter": "manualChoose"
}

中控收到后把人工介入状态写入：

afitMap[line].ait_state = 1

前端运行状态：

8：请求人工介入

前端此时可以展示人工操作按钮，例如：

  • 批次结算/退料
  • 单次抓取
  • 同设备转线
  • 强制结束当前流程

六、人工介入后的批次结算

前端调用：

POST /ait/selectTheProcess?num=1&line=1

中控执行：

  1. DeviceWebSocketHandler.ait_stripping(line)。
  2. 将 afitMap[line].ait_state=0。
  3. 向 station 下发：
{
  "command": "ait_stripping",
  "line": 1
}

station 执行：

MachinsServiceImpl.finishes(localLine, line)

步骤：

  1. 上报 9：人工选择批次结算。
  2. 写 PLC 批次结束点位：
本地产线批次结束点位
本地 1 线DB32.6.1=true
本地 2 线DB32.6.2=true
本地 3 线DB32.6.3=true
  1. 上报 11：地磅称重中。
  2. 进入 saveLabelRecordAndReportMt() 等待地磅称重。
  3. 称重完成后保存 LabelRecord 并上报 MT。
  4. 向中控发送：
{
  "command": "send_agv",
  "line": 1,
  "parameter": "stripping"
}
  1. 中控把：
theStatusOfTheMachine[line] = 2

含义：请求 AGV 退料。

  1. station 清空当前本地产线重量缓存，上报：
7：工控机退料中
  1. AGV 退料完成后调用 /amr/theFeedingIsComplete，shipping=2。
  2. 如果中控判断退料前状态不是 3，则按普通退料完成处理：
theStatusOfTheMachine[line] = 0
afitMap[line].line_state = 0

前端运行状态：

4：退料完成

此时互斥具备释放条件。

七、人工介入后的同设备转线

前端调用：

POST /ait/sameMachineTransfer?sourceLine=1&targetLine=2&operator=admin&reason=现场转线

中控校验：

  1. sourceLine 和 targetLine 必须存在。
  2. 只支持 1-14 线，暂不处理 15 线。
  3. 源产线和目标产线不能相同。
  4. 必须属于同一台机台，如 1<->2、3<->4。
  5. 只有源产线处于人工介入状态 ait_state=1 时才允许。

中控向 station 下发：

{
  "command": "sameMachineTransfer",
  "line": 1,
  "parameter": {
    "sourceLine": 1,
    "targetLine": 2,
    "operator": "admin",
    "reason": "现场转线"
  }
}

station 执行：

  1. 再次校验同机台关系。
  2. 根据目标产线写 PLC 同设备转线点位：
目标产线本地产线PLC 点位
奇数线 1/3/5/7/9/11/13本地 1 线DB32.11.4=true
偶数线 2/4/6/8/10/12/14本地 2 线DB32.11.5=true
  1. 上报源产线状态：
8：请求人工介入
  1. 等待 PLC 整理物料并进入地磅称重。
  2. 读取称重结果，保存 LabelRecord，上报 MT。
  3. 完成源产线订单。
  4. 把源产线缓存物料数据复制给目标产线。
  5. 给目标产线创建新订单。
  6. 复制批次总量、存储斗重量等生产参数到目标本地产线。
  7. 复用缓存物料数据写入 PLC，省略常规扫码。
  8. station 回传中控：
{
  "command": "sameMachineTransferComplete",
  "line": 1,
  "parameter": {
    "sourceLine": 1,
    "targetLine": 2
  }
}

中控收到完成回执后：

sourceLine:
  theStatusOfTheMachine = 0
  afitMap.ait_state = 0
  afitMap.line_state = 0
  lineRunStatus = 0

targetLine:
  theStatusOfTheMachine = 0
  afitMap.ait_state = 0
  afitMap.line_state = 1
  lineRunStatus = 6

station 随后直接对目标产线执行：

executionLogic(cachedMaterialData, targetLine)

注意：同设备转线不走常规扫码，也不写常规抓取前切线点位 DB32.10.5/DB32.10.6/DB32.11.1。

八、互斥控制逻辑

互斥核心对象：

MachineLineGuard

它维护三类状态：

字段含义
lineStatuses中控 theStatusOfTheMachine[line] 的镜像
lineStates中控 afitMap[line].line_state 的镜像
occupancies每台机台当前被哪条产线占用

互斥判断点：

场景方法作用
AGV 发送送料任务tryAcceptAgvPush()如果同机台已有其他 activeLine，拦截
AGV 到准备点/离开回调allowAgvCallback()确保回调产线和当前占用产线一致
业务状态变更beforeStatusChange()/afterStatusChange()非 0 状态会占用机台
产线运行状态变更beforeLineStateChange()/afterLineStateChange()line_state=1 会占用机台

互斥释放条件：

theStatusOfTheMachine[line] == 0
afitMap[line].line_state == 0
deliveryAssigned == false

满足以上条件时，releaseIfIdle() 会释放该机台占用。

常见释放场景：

  1. AGV 普通退料完成，shipping=2，且退料前状态不是 3。
  2. 人工批次结算后 AGV 退料完成。
  3. 同设备转线完成后，源产线被中控清零，目标产线接管占用。
  4. 人工管理接口强制重置：
POST /admin/guard/reset-line?line=1&operator=admin&reason=manual_fix
POST /admin/guard/reset-machine?machine=1&operator=admin&reason=manual_clear

不会释放互斥的场景：

  1. theStatusOfTheMachine[line]=1 请求上料。
  2. theStatusOfTheMachine[line]=2 请求退料。
  3. theStatusOfTheMachine[line]=3 请求退料且后续继续补料。
  4. afitMap[line].line_state=1 表示产线仍在运行占用。
  5. 批次未达标退料后继续叫料，状态会转为 1，不释放。

九、运行状态号给前端展示

前端查询：

GET /line-run-status/snapshot
GET /line-run-status/stream

状态字典：

状态号含义主要触发点
0无初始化、重置、批次结束归零
1AGV上料中AGV 调用 /amr/feedingInformation
2AGV到达准备点AGV 调用 /amr/preparationPoint
3送料完成开始扫码AGV 调用 /amr/theFeedingIsComplete，shipping=1
4退料完成AGV 调用 /amr/theFeedingIsComplete，shipping=2，且不是继续补料
5退料完成正在呼叫补料AGV 调用 /amr/theFeedingIsComplete，shipping=2，且退料前状态为 3
6工控机投料中station 进入 executionLogic
7工控机退料中station 退出投料循环，或人工结算后呼叫 AGV 退料
8请求人工介入PLC 达标、强制结束、同设备转线发起、人工介入
9人工选择批次结算前端选择批次结算
10PLC当前是手动模式，流程结束station 检测到 DB36.1.0=false
11地磅称重中人工批次结算后进入称重

三个容易卡住的循环及前端状态：

卡住位置前端状态号
扫码循环3
投料等待 PLC 退料信号循环6
人工结算后的地磅称重循环11

说明：正常 PLC 退料信号触发的称重等待目前公共称重方法主要打印日志，前端可能仍显示 6 或随后变成 7。如果要所有称重等待都统一显示 11，建议在 saveLabelRecordAndReportMt() 方法入口统一上报 11。

十、人工强制结束当前流程按钮

推荐按钮名称：

强制结束当前流程

接口：

POST /admin/guard/stop-execution-loop?line=1&operator=admin&reason=流程卡住

如果现场已确认清场，希望同时释放中控互斥：

POST /admin/guard/stop-execution-loop?line=1&operator=admin&reason=人工清场&resetGuard=true

中控执行：

  1. 根据 line 找到机台。
  2. 向 station 下发：
{
  "command": "stopExecutionLogic",
  "line": 1,
  "parameter": {
    "operator": "admin",
    "reason": "流程卡住"
  }
}
  1. 中控将运行状态改为 8：请求人工介入。
  2. 如果 resetGuard=true，中控同时重置业务状态并释放互斥。

station 执行：

  1. machineService.requestStopExecutionLogic() 设置投料/称重退出标记。
  2. scanCodeService.requestStopScanCode() 设置扫码退出标记。
  3. 如果当前卡在扫码循环，下一轮循环退出。
  4. 如果当前卡在等待 PLC 退料循环，下一轮 executionLogic 退出。
  5. 如果当前卡在称重循环，下一轮称重等待退出。

注意：不带 resetGuard=true 时，只退出 station 当前循环，不释放中控互斥。

十三、排查流程卡住时的判断顺序

  1. 看前端运行状态号：
  • 3：优先查扫码 PLC 信号 DB34.6.3 和二维码 DB100.1260.0。
  • 6：优先查 DB34.0.3 退料信号、DB36.1.0 自动模式、达标点位。
  • 11：优先查 DB34.16.0 称重完成信号和 DB34.18.0 重量。
  • 8：说明已进入人工介入或被强制结束，等待人工选择下一步。
  • 10：PLC 被切手动，station 已结束流程。
  1. 看中控 /admin/guard/snapshot：
  • guard.occupancies 是否仍有 activeLine。
  • processLineStatuses 是否为 1/2/3。
  • processAfitMap[line].line_state 是否仍为 1。
  1. 如果 station 只是卡住但现场没有清场：
  • 调 /admin/guard/stop-execution-loop，不带 resetGuard。
  1. 如果现场已人工清场，要释放互斥：
  • 调 /admin/guard/stop-execution-loop?...&resetGuard=true。
  • 或调 /admin/guard/reset-line。
  • 或按机台调 /admin/guard/reset-machine。
